# 2026-09-19 Dev Log

## Nickname ISO control validation

The frontend nickname validator rejected C0 controls and DEL but accepted C1
controls U+0080–U+009F. The backend `CredentialPolicy.normalizeDisplayName`
already rejects those characters through `Character.isISOControl`, so an input
such as `A\u0085B` could pass the frontend check and then be rejected on submission.
This is validation inconsistency, not a bypass of backend validation.

- Expanded only the frontend nickname control range to match the backend.
- Added `npm test` using Node's test runner and the existing TypeScript compiler;
  no new dependencies or lockfile changes.
- Added 92 frontend policy tests: all 65 embedded ISO controls, 10 allowed
  neighboring/Unicode inputs, length/trim cases and unchanged credential behavior.
- Added three backend `CredentialPolicyTest` methods covering the same control
  ranges, allowed characters and length/trim boundaries without starting Spring.
- Preserved the staff-management `allowReserved: true` username exception.
